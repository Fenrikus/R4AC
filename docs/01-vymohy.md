# 01. Цілі, обсяг та вимоги до функціоналу

> Статус: чернетка v0.1 (для обговорення). Усі цінові орієнтири — оціночні, підлягають
> підтвердженню комерційними пропозиціями (див. `05-tco.md`).

## 1. Бізнес-мета

Побудувати систему відеоспостереження у службових автомобілях (седан, SUV, мікроавтобус),
яка дозволяє **фіксувати дії персоналу в робочий час** з мінімальною сукупною вартістю
володіння та в межах законодавства України про працю й персональні дані.

### Цільові результати (для яких вимірюємо ROI)

| # | Ціль | Метрика | Базове значення | Ціль на 12 міс. |
|---|------|---------|-----------------|-----------------|
| B1 | Зменшити нецільове використання транспорту | км поза маршрутом/міс. | заміряти на пілоті | −25% |
| B2 | Скоротити витрати пального | л/100 км по автопарку | заміряти | −7…10% |
| B3 | Знизити аварійність і збитки | ДТП на 100 тис. км | заміряти | −30% |
| B4 | Скоротити час розбору інцидентів | год. на інцидент | 4–8 год | < 30 хв |
| B5 | Підтвердити виконання виїзних робіт | % візитів з відеопідтвердженням | 0% | > 95% |
| B6 | Зняти безпідставні претензії третіх осіб | к-сть виграних спорів | — | > 80% |

**Явно не є метою:** тотальний нагляд за особистим життям працівника, аудіозапис розмов,
контроль поза робочим часом. Це і юридичний ризик, і головний драйвер опору персоналу.

## 2. Обсяг (Scope)

**У межах проєкту:**
- Бортове обладнання (реєстратор + камери + GNSS/акселерометр + 4G) для 3 типів кузова.
- Передача, зберігання та перегляд відео і телеметрії.
- Події (ДТП, різке гальмування, втома/відволікання водія, вихід із маршруту, простій).
- Ролі, доступи, журнал аудиту переглядів.
- Політики, накази, згоди, інструктаж персоналу.
- Звітність та інтеграція з обліком (дорожні листи / ERP / HR).

**Поза межами (фаза 2+):** розпізнавання облич пасажирів, біометрична ідентифікація водія,
контроль вантажу через ваги, підрахунок пасажиропотоку, аудіозапис у салоні.

## 3. Актори системи

| Актор | Потреба |
|-------|---------|
| Водій / виїзний працівник | прозорі правила, зворотний зв'язок, захист від наклепу |
| Керівник підрозділу | контроль виконання завдань, дисципліни, маршрутів |
| Диспетчер / логіст | онлайн-локація, стан авто, реакція на інциденти |
| Служба безпеки | розслідування інцидентів, доступ до архіву за регламентом |
| Механік / автогосподарство | стиль водіння, техстан, пробіг |
| Юрист / DPO | законність обробки, реагування на запити суб'єктів даних |
| Адмін системи | пристрої, оновлення, доступи, ретенція |

## 5. Нефункціональні вимоги

| ID | Категорія | Вимога |
|----|-----------|--------|
| NFR-01 | Доступність | Платформа 99,5% (SaaS) / 99,0% (self-hosted), RPO ≤ 1 год, RTO ≤ 4 год |
| NFR-02 | Масштаб | Старт 30 авто, проєктування без переробки до 300 авто |
| NFR-03 | Ретенція | Борт: 7–14 діб безперервного відео; хмара: події 90 діб, інциденти — до закриття справи |
| NFR-04 | Безпека каналу | TLS 1.2+ / mTLS для пристроїв; заборона немаршрутизованих відкритих портів |
| NFR-05 | Шифрування | Шифрування архіву в хмарі (at rest); бажано — шифрування носія на борту |
| NFR-06 | Локалізація даних | Зберігання в ЄС або в Україні; трансфер поза ЄС — лише за SCC (див. `06-pravo.md`) |
| NFR-07 | Умови експлуатації | −30…+70 °C, вібростійкість, живлення 9–36 В, захист від глибокого розряду АКБ |
| NFR-08 | Енергоспоживання | ≤ 10 мА у сплячому режимі; автовимкнення при напрузі < 11,8 В |
| NFR-09 | Зв'язок | 4G LTE (Cat.1/Cat.4), 2 SIM (основна + резервна, різні оператори) або eSIM з мультипрофілем |
| NFR-10 | Трафік | ≤ 3 ГБ/авто/міс. у штатному режимі (події + до 1 год live) |
| NFR-11 | Юзабіліті | Знайти й вивантажити потрібний фрагмент — ≤ 3 хв, ≤ 5 кліків |
| NFR-12 | Мова | Інтерфейс UA (обов'язково), EN (бажано) |
| NFR-13 | Vendor lock-in | Обладнання має підтримувати ≥ 2 платформи (стандартні протоколи), експорт даних без втрат |
| NFR-14 | Обслуговуваність | Заміна пристрою на авто ≤ 2 год, без демонтажу панелей більше ніж на 1 год |
| NFR-15 | Воєнні ризики | Робота при глушінні GNSS (числення шляху за акселерометром/одометром), без залежності від одного ЦОД |

## 6. Критерії приймання (Definition of Done для пілоту)

1. 100% авто пілоту передають телеметрію та відео ≥ 95% робочого часу.
2. Час від критичної події до сповіщення диспетчера ≤ 3 хв.
3. Успішне вивантаження доказового пакета за 3 навчальними інцидентами.
4. Середній трафік на авто ≤ 3 ГБ/міс.
5. Наказ, положення, згоди підписані 100% залучених працівників; журнал аудиту працює.
6. Питомі витрати на авто/міс. не перевищують затвердженого бюджету (див. `05-tco.md`).
